# تحلیل‌گر اتصال اینترنت و پروتکل‌ها (نسخه‌ی ۲)

[English README](README.md)

یک ابزار دسکتاپ برای کاربران عادی که با **Python 3.12+** و **PySide6** ساخته شده است و کمک می‌کند بفهمید چرا اتصال اینترنت‌تان کند، محدود یا بخشی از آن مسدود است. برای استفاده از آن لازم نیست دانش شبکه داشته باشید.

> **نکته‌ی دامنه‌ی کار:** این ابزار فقط **تشخیص** می‌دهد. هیچ‌وقت تلاشی برای دور زدن محدودیت‌ها نمی‌کند و هیچ‌وقت ادعای قطعی درباره‌ی سانسور نمی‌کند؛ فقط تفسیرهای احتیاط‌آمیز و احتمالی از چیزی که مشاهده شده ارائه می‌دهد.

---

## قابلیت‌ها

- **صفحه‌ی خانه:** آی‌پی عمومی، ISP، کشور/شهر، وضعیت IPv4/IPv6، سرورهای DNS، کارت شبکه، گیت‌وی و وضعیت کلی اینترنت.
- **تشخیص پروکسی و VPN:** بررسی پروکسی سیستم، برنامه‌های در حال گوش دادن روی پورت‌های رایج پروکسی محلی و کارت‌های شبکه‌ی VPN/TUN. اگر تونل فعال باشد، همه‌ی نتایج دیگر مربوط به تونل است و گزارش این را می‌گوید.
- **اتصال پایه:** پینگ، traceroute، تبدیل نام DNS و درخواست HTTP/HTTPS.
- **تست DNS:** پرس‌وجو مستقیم از Google / Cloudflare / Quad9 / OpenDNS، به‌علاوه‌ی DNS سیستم و DNS-over-HTTPS، و جست‌وجوی سرور پرت یا پاسخ‌های شبیه صفحه‌ی مسدودسازی (آدرس خصوصی یا loopback).
- **اسکنر پورت TCP:** محدود به فهرست ثابتی از پورت‌های شناخته‌شده؛ وضعیت open / closed / filtered / timeout / reset را همراه با تأخیر گزارش می‌دهد.
- **تست UDP:** بررسی دسترس‌پذیری روی پورت‌های 53 / 123 / 443 / 500 / 4500 / 51820.
- **تست TLS:** نسخه‌های TLS 1.2 و 1.3، اعتبارسنجی گواهی، زمان handshake، SNI، ALPN، cipher suite، و بررسی فیلترینگ SNI (یک سرور با نام‌های SNI متفاوت).
- **تست HTTP:** HTTP، HTTPS، HTTP/2، HTTP/3 (QUIC)، ریدایرکت‌ها، فشرده‌سازی، بررسی واقعی keep-alive و تشخیص صفحه‌ی مسدودسازی (کد 451 یا ریدایرکت/iframe به آدرس‌های خصوصی).
- **تست توقف TCP:** تشخیص اتصال‌هایی که درست شروع می‌شوند و بعد از حدود ۱۰ تا ۴۰ کیلوبایت قطع می‌شوند (الگوی «۱۶ تا ۲۰ کیلوبایت»).
- **دسترس‌پذیری وب‌سایت‌ها:** بررسی لایه‌به‌لایه‌ی سایت‌ها (DNS، TCP، TLS، HTTPS) و گزارش اولین لایه‌ای که شکست می‌خورد، در مقایسه با سایت‌های شاهد. فهرست سایت‌ها را می‌توانید در تب پیشرفته تغییر دهید.
- **تست پروتکل‌ها:** انتقال QUIC، DoH، DoT، ICMP و WebSocket.
- **تست تأخیر:** پینگ چندهدفه؛ میانگین، از دست رفتن بسته و jitter.
- **تست MTU:** برآورد MTU مسیر با جست‌وجوی دودویی روی پینگ با پرچم DF.
- **اتصال مرتبط با VPN:** فقط دسترس‌پذیری خام پورت‌های رایج انتقال VPN؛ هرگز به VPN وصل نمی‌شود و نمی‌گوید یک VPN «کار می‌کند».
- **بررسی فهرست سفید پروتکل (اختیاری، پیش‌فرض خاموش):** بررسی وجود فیلتری که روی پورت 443 فقط پروتکل‌های شناخته‌شده را عبور می‌دهد. ممکن است باعث شود فیلتر حدود یک دقیقه بسته‌های شما را رها کند؛ بنابراین قبل از اجرا تأیید می‌گیرد.
- **شبکه‌ی محلی و گیت‌وی:** رابط محلی، مسیر پیش‌فرض و تست گیت‌وی (اول ICMP و بعد TCP؛ سکوت روتر فقط یک نشانه است نه حکم قطعی).
- **موتور تحلیل:** موتور همبستگی همه‌ی نتایج را کنار هم بررسی می‌کند و تشخیص‌هایی با سطح اطمینان («شناسایی شد / محتمل / ممکن / نامشخص») همراه با شواهد آن‌ها تولید می‌کند. گزارش در چهار لایه است: خلاصه‌ی کلی، یافته‌های کلیدی، شواهد فنی و علت ریشه‌ای.
- **تب عیب‌یابی:** انتخاب تست‌ها، تکرار اجرا به تعداد دلخواه با فاصله، و توقف در هر لحظه؛ کارت‌های خاکستری تست‌های در انتظار یا اجرا نشده را نشان می‌دهند.
- **تب تاریخچه:** هر اجرای کامل‌شده خودکار ذخیره می‌شود و می‌توانید هر دو اجرا را مقایسه کنید.
- **خروجی گرفتن:** TXT، JSON، CSV و گزارش HTML مستقل (متن نامطمئن escape می‌شود و سلول‌های CSV نمی‌توانند به‌عنوان فرمول اجرا شوند).
- **حالت پیشرفته:** میزبان هدف دلخواه، پورت‌ها، فهرست وب‌سایت‌ها و پروفایل‌های ذخیره‌شده.
- **لاگ:** فایل‌های لاگ روزانه و یک خط خلاصه برای هر اجرا (زمان، مدت، خطاها، اطلاعات شبکه).
- **رابط فارسی و انگلیسی:** برنامه به‌صورت پیش‌فرض فارسی و راست‌به‌چپ شروع می‌شود و از منوی زبان هر زمان قابل تغییر است. خروجی‌ها هم از زبان انتخابی پیروی می‌کنند؛ فقط JSON همیشه انگلیسی می‌ماند تا گزارش‌های ذخیره‌شده قابل مقایسه باشند.
- **بدون نیاز به دسترسی ادمین.** هر ماژول ایزوله است؛ خطا در یک ماژول به نتیجه‌ی UNKNOWN تبدیل می‌شود و برنامه کرش نمی‌کند.

## ساختار پروژه

```text
internet_analyzer/
├── main.py                نقطه‌ی ورود
├── requirements.txt / requirements-dev.txt
├── build.spec             فایل PyInstaller
├── tests/                 تست‌های pytest (بدون نیاز به اینترنت)
└── app/
    ├── constants.py       مقادیر ثابت (پورت‌ها، timeoutها، آدرس‌ها)
    ├── config.py          مسیرها و تنظیمات ذخیره‌شده
    ├── logger.py          لاگ در فایل و حافظه
    ├── i18n.py / i18n_fa.py   موتور ترجمه و متن‌های فارسی (پشتیبانی RTL)
    ├── models.py          مدل‌های داده‌ی مشترک
    ├── core/              منطق همه‌ی تست‌ها (بدون ویجت)
    ├── diag/              موتور لایه‌ای: مدل TestResult، نرمال‌سازی خطاها
    │                      (از جمله کدهای WSA ویندوز)، سیاست تلاش مجدد،
    │                      گراف وابستگی، موتور همبستگی، لایه‌های گزارش
    ├── gui/               رابط PySide6 (خانه، عیب‌یابی، پیشرفته، تاریخچه، لاگ)
    ├── export/            خروجی TXT/JSON/CSV/HTML و تاریخچه
    ├── utils/             توابع کمکی
    └── assets/fonts/      فونت‌های Google Sans و Vazirmatn (OFL)
```

## اجرا از روی سورس

```bash
python -m venv venv
venv\Scripts\activate        # ویندوز
pip install -r requirements.txt
python main.py
```

در ویندوز می‌توانید فایل `run.bat` را هم دوبار کلیک کنید (برنامه را اجرا می‌کند و اگر خطایی رخ دهد پنجره را باز نگه می‌دارد).

اجرای تست‌ها (بدون نیاز به اینترنت):

```bash
pip install -r requirements-dev.txt
pytest
```

پیش‌نیاز: Python 3.12 یا بالاتر. پلتفرم هدف: ویندوز ۱۰ و ویندوز ۱۱.

## ساخت فایل اجرایی (.exe)

```bash
pip install -r requirements.txt
pyinstaller build.spec
```

خروجی در مسیر `dist/ICPA/ICPA.exe` ساخته می‌شود. همه‌ی داده‌های برنامه (لاگ‌ها، گزارش‌ها، تاریخچه، پروفایل‌ها و تنظیمات) در `%LOCALAPPDATA%\ICPA` ذخیره می‌شود، نه کنار فایل اجرایی.

## نکات طراحی

- **تشخیص بله، دور زدن نه.** هیچ کد دور زدن محدودیت در پروژه نیست. بررسی‌های SNI، توقف و فهرست سفید فقط رفتار اتصال‌ها را مشاهده می‌کنند.
- **زبان احتیاطی.** یک تست سمت کاربر نمی‌تواند قصد را ثابت کند؛ به همین دلیل هر تفسیر از عباراتی مثل «ممکن است»، «سازگار با» یا «یک احتمال» استفاده می‌کند.
- **مقایسه با سایت‌های شاهد.** نتیجه‌ی هر سایت فقط وقتی معنا دارد که سایت‌های شاهد کار کنند؛ گزارش این را مقایسه می‌کند و اگر شاهدها هم شکست بخورند می‌گوید.
- **تحلیل مستقل از زبان.** ویندوز کلمه‌ی «time» در خروجی ping و بعضی متن‌های خطا را ترجمه می‌کند؛ بنابراین پاسخ‌ها با نشانه‌ی `TTL=` شناسایی می‌شوند و روی ویندوز غیرانگلیسی هم نتیجه درست است.
- **اعتبارسنجی ورودی.** ورودی کاربر قبل از رسیدن به ping/tracert بررسی می‌شود (بدون `-` ابتدایی و بدون فاصله) و انتخاب پورت به فهرست ثابت محدود است.
- **اسکن TCP عمومی نیست.** اسکن فقط چند میزبان anycast همیشه‌روشن یا میزبانی را که خودتان وارد می‌کنید هدف می‌گیرد؛ این یک بررسی دسترس‌پذیری است، نه اسکنر پورت عمومی.
- **HTTP/3.** اگر aioquic نصب باشد از handshake واقعی QUIC استفاده می‌شود، وگرنه از اشاره‌ی Alt-Svc که به‌عنوان همین برچسب‌گذاری شده است.
- **مشاهده جدا از تفسیر.** هر نتیجه یک وضعیت فنی دارد (TIMEOUT هرگز به‌عنوان CLOSED گزارش نمی‌شود)، یک شدت، و فقط جایی که چیزی استنباط شده، یک تفسیر همراه با درجه‌ی اطمینان.
- **اجرای آگاه از وابستگی.** ماژول‌های مستقل موازی اجرا می‌شوند؛ اگر DNS سیستم قطعاً خراب باشد، تست‌های مبتنی بر نام (TLS، HTTP، وب‌سایت‌ها) با برچسب «رد شده» نادیده گرفته می‌شوند تا یک علت ریشه‌ای مثل ده شکست دیده نشود.
- **لاگ‌ها.** فایل‌های `icpa_YYYYMMDD.log` (خوانا) و `icpa_YYYYMMDD.jsonl` (هر خط یک شیء JSON). جزئیات بیشتر در `docs/REFACTOR_NOTES.md`.
- **ترجمه فقط برای نمایش است.** نام تست‌ها و پیام‌ها به انگلیسی تولید می‌شوند و هنگام نمایش یا خروجی گرفتن ترجمه می‌شوند؛ پس تاریخچه، مقایسه و JSON به زبان رابط وابسته نیستند. متنی که ترجمه ندارد به‌جای حذف شدن، به انگلیسی نمایش داده می‌شود. یک تست خودکار بررسی می‌کند که پیام‌های ماژول‌های تست ترجمه‌ی فارسی داشته باشند. برای افزودن زبان جدید، یک فایل داده مثل `i18n_fa.py` بسازید و آن را در `i18n.py` ثبت کنید.

## فونت‌ها

رابط کاربری از Google Sans برای متن لاتین و وزیرمتن (Vazirmatn) برای متن فارسی استفاده می‌کند. هر دو در `app/assets/fonts` همراه پروژه هستند و با مجوز SIL Open Font License 1.1 منتشر شده‌اند (فایل‌های مجوز کنار فونت‌ها قرار دارند).

## منابع و قدردانی

ایده‌های روش‌شناسی از پروژه‌ها و پژوهش‌های عمومی گرفته شده است. هیچ کد یا فهرست دامنه‌ای کپی نشده و کد این پروژه کاملاً اصیل است.

- [Runnin4ik/dpi-detector](https://github.com/Runnin4ik/dpi-detector) (MIT): ایده‌ی تست توقف TCP در ۱۶ تا ۲۰ کیلوبایت و جداسازی انواع خطا.
- [MayersScott/rkn-block-checker](https://github.com/MayersScott/rkn-block-checker) (MIT): بررسی لایه‌ای DNS/TCP/TLS/HTTP، مقایسه‌ی DNS سیستم با DoH، و «TCP کار می‌کند ولی TLS شکست می‌خورد» به‌عنوان نشانه‌ی بازرسی ClientHello.
- [OONI Probe](https://ooni.org/install/): مرجع اندازه‌گیری باز شبکه.
- Bock et al., *Detecting and Evading Censorship-in-Depth: A Case Study of Iran's Protocol Filter* (FOCI 2020): مبنای بررسی اختیاری فهرست سفید پروتکل. ممکن است رفتار فیلتر پس از آن پژوهش تغییر کرده باشد.
- [bepass-org/oblivion-desktop](https://github.com/bepass-org/oblivion-desktop): پورت‌های محلی مستند (8086، 8087، 50051) که در تشخیص پروکسی استفاده می‌شوند.
